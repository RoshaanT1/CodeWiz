# Supabase TOTP 2FA for Next.js App Router

## Description

Drop-in two-factor authentication for a Next.js App Router app using Supabase Auth MFA. It includes TOTP enrolment with a QR code and manual secret, a verification screen for every password sign-in, middleware redirects, server component guards, API route guards, and database policies that require an `aal2` session.

## Skills

Next.js, React, TypeScript, Supabase, PostgreSQL

## Custom tags

2FA, TOTP, MFA, authentication, Row Level Security, App Router

## What it does

- Redirects signed-in users with no verified TOTP factor to `/2fa/enrol`.
- Redirects enrolled users whose current session is still `aal1` to `/2fa/verify`.
- Uses `supabase.auth.mfa.enroll`, `challenge`, and `verify` / `challengeAndVerify` flow to promote the session to `aal2`.
- Provides `requireAal2User()` for Server Components and `requireApiAal2Session()` for route handlers.
- Complements Supabase Row Level Security policies that check `(select auth.jwt()->>'aal') = 'aal2'`.

## Install

```bash
npm install next react react-dom @supabase/ssr @supabase/supabase-js
```

## Setup

1. Create a Supabase project and enable Email auth.
2. In Supabase Auth, enable MFA with TOTP factors.
3. Add these variables to your environment:

```bash
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
```

4. Use `@supabase/ssr` clients so the browser, route handlers and middleware share the same cookie-backed session.
5. Add RLS policies that require both the signed-in user and an AAL2 session:

```sql
using (
  user_id = (select auth.uid())
  and (select auth.jwt()->>'aal') = 'aal2'
)
```

## Usage example

Protect pages in middleware before they render:

```ts
if (user && isProtectedPath(pathname)) {
  if (aal.nextLevel === "aal1") {
    const enrol = new URL("/2fa/enrol", origin);
    enrol.searchParams.set("next", `${pathname}${search}`);
    return redirectWithCookies(enrol, response);
  }

  if (aal.nextLevel === "aal2" && aal.currentLevel !== "aal2") {
    const verify = new URL("/2fa/verify", origin);
    verify.searchParams.set("next", `${pathname}${search}`);
    return redirectWithCookies(verify, response);
  }
}
```

Protect Server Components too:

```ts
import { requireAal2User } from "@/lib/auth/session";

export default async function DashboardPage() {
  const user = await requireAal2User("/dashboard");
  return <p>Signed in as {user.email}</p>;
}
```

Protect route handlers:

```ts
const session = await requireApiAal2Session();
if (!session.ok) {
  return Response.json({ ok: false, error: session.reason }, { status: session.status });
}
```

## Options and limits

- The sample protects `/dashboard`; add more protected prefixes in `lib/auth/redirect.ts`.
- `next` redirects are sanitized to in-app paths only.
- TOTP codes are generated by the user's authenticator app and usually rotate every 30 seconds.
- Supabase determines `currentLevel` and `nextLevel`; the app should not infer 2FA state from local storage or user metadata.
- API guards return JSON errors instead of redirects so clients can show a friendly message.
